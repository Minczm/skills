# HTML 报告与神经网络式关系图

目录：阅读顺序；八个入口；八个问题；十一类档案；主体与案例；关系图；视觉；复用模板。

## 一、阅读顺序

首页先解释目标公司，再沿相关的人、公司、资本和产品深入。每条主线交代连接事实与理解公司的作用。新材料回填对应判断、主体和案例，维持完整的公司叙事。

以五分钟理解为首页目标：清楚说出公司做什么、由谁持有和经营、业务怎样赚钱、本次选择最受哪些事实影响。把重点证据的日期与适用范围放在附近；主张细节、长履历、完整股东链和原始附件通过展开或档案入口阅读。首屏保留核心判断和明显的继续阅读入口。

默认三层阅读：

1. 快速认识：公司业务、法律主体、关键人物、经营方式和最重要发现。
2. 理解关系：人物及关联公司主线、实际案例、业务/资金流程与核心问题。
3. 查阅档案：全部主体、历史事实、原始来源、实图、时间线及可复用资料。

用户实际提供或指定已有成稿时，保留其可用结构与认可的入口。首次调查使用下列默认组织，按行业和法域调整栏目措辞。示例中的公司、问题或风格不带入新任务。

## 二、默认八个阅读入口

| 入口 | 应直接回答的内容 | 适合呈现 |
| --- | --- | --- |
| 01 先认识公司 | 实际业务、法律主体、关键判断与证据 | 导语、事实卡、真实官网或业务图像 |
| 02 股东与人员沿革 | 权益、经营负责人、治理与人员变化 | 股东表、人物卡、时间线 |
| 03 关联公司主线 | 通过谁或什么连接到哪些主体 | 关系网络、逐支说明、主体档案 |
| 04 业务与资金 | 客户、交付、获客/采购、收费、成本和收益分配 | 业务流、资金流、精确金额对照 |
| 05 重点案例 | 产品或项目、目标公司角色、成果与维护 | 实图案例卡、版本/交付时间线 |
| 06 团队与发展 | 人数口径、岗位五维、雇佣主体、发展与资质 | 关键工作解释、团队/岗位记录、发展时间线 |
| 07 核心问题 | 本次最关心问题的回答及证据 | 可展开问答、相关主体链接 |
| 08 完整资料档案 | 深入查阅全部事实、来源和历史 | 分类档案、搜索、来源索引与导出 |

首页数字标明日期与范围，直接从资料计算。标题和问题可适应任务，核心覆盖保持完整。

有可比经营数据时，用 `metrics` 呈现少量关键数字，正文用 `block.chart` 比较同口径期间或组成，用 `block.table` 展示精确对照。主张按钮按需展开事实类型、时间、定位和实际留存状态；完整来源索引保留原始 URL。字段见 [data-model.md](data-model.md)。

## 三、默认八个核心问题

将问题改写为适合目标公司的自然表达；更新真实旧报告时保留已有问题身份。

1. 谁持有和经营公司，治理及人员如何变化？
2. 公司实际向谁提供什么，交付能力体现在哪里？
3. 哪些关联主体最有助于理解公司，各通过什么事实连接？
4. 重点产品或项目体现了哪些可核验的工作与成果？
5. 项目、生产或增长费用由谁承担，收入怎样回到公司？
6. 公司经过怎样的发展形成当前业务？
7. 团队人数、岗位、工作地点和雇佣主体分别是什么口径？
8. 哪些公开差异、争议或经营事实最影响当前判断？

每题给当前回答、具体支持事实、相关人物/公司/产品入口及经营含义。证据按问题需要组织，实际缺口在该题集中说明一次。

入职或岗位调查把第七题具体化为实际工作、运行流程、所需经验、行业知识和工作条件，并将最影响选择的答案带回首页。保留公司中心的八问结构。

## 四、默认十一类资料档案

1. 主要法域的登记主体、股东与治理。
2. 其他法域主体与运营、发行或销售迁移。
3. 全部关键人物、履历与任职。
4. 完整产品、项目与案例图集。
5. 股权与其他具体关系分图。
6. 资本金额、财务与各期业务指标。
7. 网站实图、域名和适用的站点登记/备案。
8. 招聘、雇佣主体与团队。
9. 公开差异、客诉、司法行政记录及其他争议。
10. 完整发展时间线。
11. 全部原始材料、主张依据与证据留存清单。

按调查实际合并空栏目或调整名称。保留真实旧稿仍有效的历史资料。档案引用统一主体、来源与图片记录，使正文、图谱和详情同步。

## 五、人物、公司与案例

### 人物档案

依次呈现与目标公司的连接路径、当前/历史角色、关键工作、履历、权益和任职、相关公司及产品、出处。履历使用有证据的时间线；“合伙人”“负责人”等称呼注明具体职责和材料时间。用户指定人物可由全站搜索、图谱和人物目录直接找到。同音异人搜索结果分别列出可辨认的职业信息。

### 公司档案

依次呈现连接路径、法律全称/法域/登记号、登记与经营状态、股东和管理、对应业务、产品/客户/供应商、关键事件与来源。将共同股东、任职、采购、开发、运营和发行关系准确命名。必要时保留原文法律术语及简明解释。

### 产品与项目案例

以真实图片、精确角色和完整解释组织重点案例，其他案例放入可检索图集：

- 产品、型号、稳定 ID 或项目名称，以及市场/平台和有效时间。
- 解决的问题、客户需要及目标公司承担的具体工作。
- 创作者、权利主体、开发者、制造者、运营者、发行/经销方和客户。
- 原始公布成果及后续观察，附指标定义、日期、分母和说话主体。
- 收费、采购、订阅、售后、客服、更新及维护记录。
- 关键事件、问题反馈、回应和已知结果。
- 原始材料及实际页面、产品或附件图像。

按行业绘制“获客或采购—交付—结算—维护”流程。资金流独立标出谁付款、谁收款、计费依据和期间。用户从案例可以继续打开相关人物或公司。

## 六、神经网络式关系图

### 含义与数据

使用公司为根节点的可探索关系网，按人物、公司、品牌、产品、基金和机构分型。布局围绕直接连接和业务主线聚类，保留跨支关系。节点距离、面积和颜色只表达图例定义的信息，控制与权益依具体关系事实呈现。

持股、出资与投资可用实线，任职、创作、开发、运营、发行和合作可用虚线；历史、候选和争议使用清晰状态。颜色之外保留线型、图标或文字，便于不同视觉条件阅读。边详情逐条展示同一主体对的不同事实、日期与来源。

### 三种视图

- 核心网络：默认显示最有解释价值的主体，并保留通向公司根节点的中间节点。
- 全部主体：提供完整探索，次要名称适当收起，搜索或点选后聚焦。
- 所选周边：显示所选主体的直接关系及其回到公司的路径。

### 必要交互

支持姓名/全称/别名/产品搜索、视图切换、缩放、适配画布、节点与画布拖动、全屏、返回根节点、打开主体档案及连线事实。搜索结果标明主体类型和身份信息，避免同名混淆。

导航路径可以双向查找，展示时恢复原始箭头，例如 `公司甲 ← 股东乙 → 公司丙`。每一步附关系、有效日期和出处。默认确认路径遵循可确认的关系；候选和争议状态单独显示，历史路径注明时间。权益或控制分析采用相应资本和治理材料。

### 可读性与可访问性

根节点突出，次级节点按明确类型和重要性区分。长名称在图上缩短，在详情显示全称。布局稳定，控制标签密度、交叉、遮挡和点击区域。全图过密时保持可读核心图与聚焦能力。

提供图谱对应的列表或档案入口，便于键盘和小屏阅读。手机保留搜索、展开与主体详情；点选后立即出现可读内容。对话框有标题、关闭操作和清晰焦点，关闭后回到触发处。信息不只依靠悬停显示。

## 七、视觉与页面表现

有实际旧稿时延续其适用设计；首次制作选择清晰、克制的视觉系统。中性背景、足够对比的正文、统一强调色和主体类型色即可。暖白与深绿可作为可选组合，色彩服从品牌要求和可读性。

采用系统字体和适合报告语言的字号、行高及行宽。桌面目录便于持续定位，小屏目录可展开。正文组合段落、卡片、时间线、流程与必要的小表格。避免用大表承载所有产品故事。

全站搜索覆盖正文、主体、别名、产品和来源；搜索结果可直接打开内容。图片维持原比例并支持放大，图注附来源与日期。无实际内容的栏目可自然省略。

将 CSS、JavaScript、数据和主要图像嵌入一个 HTML，保留原始来源链接。离线可阅读正文和主要交互。打印隐藏操作控件，展开核心正文、完整档案和详情资料，保留来源标题及地址，避免长卡片截断。

采用 claims 时，打印附录纳入主张、日期、定位、来源与推理，保持弹层中的关键依据可在纸面查阅。

页面仅呈现调查事实、必要解释和操作词。资料合并、实现架构、调试与验证过程留在内部记录。外部原文作为转义后的文本或已核验图像进入报告。

主张及存档细节收在依据弹层和来源档案，首页维持阅读节奏。日期缺失按一次实际未知表达；哈希与文件路径用于深入核对，正文优先解释其支持的事实。

## 八、复用模板

随附 `assets/report.html`、`assets/report.css`、`assets/report.js` 提供结构、样式与交互；`scripts/build_report.py` 可将调查 JSON 和实际取得的图片构建为单文件。解析当前技能目录后使用这些相对资源，按运行时和报告需要调整。

模板用于首次制作或合适的改版；真实旧报告优先保留可用结构。演示数据只用于了解字段及试运行，正式调查以本次取得的事实替换。构建后实际打开文件，验收来源入口、搜索、图谱、移动端与打印。
